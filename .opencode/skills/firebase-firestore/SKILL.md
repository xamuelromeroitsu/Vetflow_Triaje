# Cloud Firestore Database and Operations

> [!IMPORTANT] **Security Rules Authoring (`firestore.rules`)** Whenever your
> task requires creating, authoring, or modifying `firestore.rules`:
>
> - **If subagent delegation AND the `firestore-rules-author` subagent are
>   available**: delegate authoring `firestore.rules` to the
>   `firestore-rules-author` subagent rather than writing `firestore.rules`
>   directly in the main agent.
> - **If subagent delegation is unavailable** (e.g., subagents not enabled in
>   the IDE) **OR `firestore-rules-author` is not installed**: read and follow
>   the `firestore-rules-creation` skill to write `firestore.rules` directly.

Before setting up dependencies, writing data models, or configuring security
rules, confirm the Firestore edition. This project uses **Standard edition**
(the default for most apps). Run:

```bash
npx -y firebase-tools@latest firestore:databases:list
```

- If a database exists and its `edition` is `STANDARD`, follow the guides under
  `references/standard/`.
- If the edition is `ENTERPRISE` (native mode), tell the user: the guides for
  that edition are not kept in this repo (they were trimmed to Standard/Flutter
  only). Point them to the official Firebase Agent Skills repository and ask
  before reverting this trim.
- If no database exists, ask the user for the location, then create the
  Standard edition database:

  ```bash
  npx -y firebase-tools@latest firestore:locations
  npx -y firebase-tools@latest firestore:databases:create "(default)" --edition="standard" --location="<selected-location>"
  ```

  Proceed with the guides under `references/standard/`.

## Flutter SDK (this project)

- Package: `cloud_firestore` (already in `vetflow_triaje/pubspec.yaml`).
- Initialization is done in `lib/main.dart` after
  `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)`
  (options generated by `flutterfire configure`).
- Offline persistence is enabled by default on mobile; keep it enabled.
